RCA AI Agent 사전학습 지도

Stanford 공개 강좌를 RCA/AI Agent 관점으로 다시 묶은 한국어 요약입니다. 영어 강의를 전부 보기 전에, 먼저 이 지도로 큰 산맥을 잡으면 됩니다.

10분 버전

이번 자료의 메시지는 간단합니다.

AI를 겉으로만 쓰지 말고, 안쪽 엔진과 평가 방법까지 이해하자.

RCA Agent는 말 잘하는 챗봇이면 부족합니다. 장애 신호를 받고, 근거를 찾고, 원인 후보를 세우고, 틀린 후보를 버리고, 위험한 조치는 사람 승인 앞에서 멈춰야 합니다.

다섯 강좌를 한 장으로

CS230 · 기초 체력

딥러닝 프로젝트를 망하지 않게 굴리는 법. error analysis, ablation, interpretability가 RCA 개선 습관으로 이어집니다.

CME295 · 세계지도

Transformer, LLM, RAG, Agent, LLM-as-judge를 빠르게 훑는 지도입니다. 팀 공통 언어 만들기에 좋습니다.

CS336 · 엔진 분해

토큰화, 모델 구조, GPU, inference, data, alignment까지 LLM을 밑바닥부터 보는 강좌입니다.

CS329H · 심판 수련

사람 선호, reward, DPO, RLHF, 평가의 함정을 배웁니다. 좋은 RCA 보고서를 비교하는 기준이 됩니다.

CS231n · 눈 수련

이미지, 영상, 대시보드를 보는 AI의 기초입니다. 로그 밖의 화면 증거를 다룰 때 중요합니다.

왜 권위 있는 자료인가

자료권위 포인트
CS230Andrew Ng와 Kian Katanforoosh가 이끄는 Stanford Deep Learning 강좌. AI 교육의 표준에 가깝습니다.
CS231nFei-Fei Li가 연결된 컴퓨터비전 대표 강좌. ImageNet 이후 비전 딥러닝의 핵심 흐름을 담습니다.
CS336Percy Liang, Tatsunori Hashimoto가 참여하는 LLM from scratch 강좌. 2026년 공식 페이지가 살아 있습니다.
CS329HMachine Learning from Human Preferences. preference learning과 평가/정렬을 체계적으로 다룹니다.
CME295Transformer와 LLM을 빠르게 정리하는 Stanford 강좌. RAG, Agent, LLM evaluation까지 이어집니다.

RCA Agent로 번역하면

좋은 RCA는 멋진 문장이 아닙니다. 아래 5개가 맞아야 합니다.

  1. 사실이 맞다.
  2. 로그, 메트릭, 트레이스 같은 근거가 있다.
  3. 원인 후보와 반증 과정이 보인다.
  4. 조치안이 안전하다.
  5. 운영자가 다음 행동을 바로 결정할 수 있다.

무협식 기억법

CS230은 기초 내공입니다. 자세가 무너지면 아무 기술도 안 통합니다.

CME295는 천하 지도입니다. 어느 문파가 어디 있는지 알아야 길을 잃지 않습니다.

CS336은 검을 분해하는 장인 수련입니다. 칼날, 손잡이, 무게중심을 알아야 진짜로 쓸 수 있습니다.

CS329H는 비무장의 심판입니다. 누가 더 강한지 그냥 느낌으로 고르면 안 됩니다.

CS231n은 천리안입니다. 글뿐 아니라 그림, 차트, 화면의 기세까지 봅니다.

여행 중 5일 루틴

  1. Day 1: CME295로 LLM/RAG/Agent/Eval 지도를 잡습니다.
  2. Day 2: CS336으로 tokenization, inference, data 품질 감각을 잡습니다.
  3. Day 3: CS329H로 좋은 RCA 보고서의 비교 기준을 만듭니다.
  4. Day 4: CS231n으로 dashboard, chart, topology를 보는 AI를 상상합니다.
  5. Day 5: Alert → Evidence → Hypothesis → Tool → Report → Approval 흐름으로 합칩니다.

2026년에 추가로 봐야 할 것

  • MCP / A2A: Agent가 도구와 다른 Agent와 연결되는 표준 흐름입니다.
  • LLM-as-judge bias: AI 심판도 편향됩니다. 사람 기준 golden set이 필요합니다.
  • Reasoning RL / GRPO: 검증 가능한 문제에서 reasoning model이 강해진 이유입니다.
  • Serving systems: 실서비스는 정확도만이 아니라 latency, cost, throughput 싸움입니다.
  • PII / audit trail: 운영 로그는 민감 데이터입니다. 마스킹과 추적이 기본입니다.
